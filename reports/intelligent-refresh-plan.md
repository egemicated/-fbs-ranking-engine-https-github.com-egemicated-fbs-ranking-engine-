# The Games Decide intelligent refresh plan

This is the isolated development proposal. Production currently checks football results at **12:45 a.m. and 2:45 a.m. Mountain**, the normal conversions of 2:45 a.m. and 4:45 a.m. `America/New_York`. Football, conference availability and account workflows remain in production as configured. No basketball workflow or revised schedule has been enabled.

## Proposed timetable for review

Primary recommendation for **football** is to retain its existing times while collecting post-change reliability evidence. Trialing 1:45 a.m. with a 3:45 a.m. recovery on the historical schedule did not beat the existing times in this sample. Keep provider deadlines separate. An active run or verified, useful primary publication suppresses recovery. Coverage still missing after a provider poll is recorded distinctly from a healthy no-op, and must pass the same quota and idempotency guards.

The potential two-call basketball cadence above describes a narrower operational window. The existing current-season backfill/refresh CLI independently supports the tested 14-day correction lookback and resynchronizes future schedule partitions, so it can use more calls. A deployed runner still has to wire the planner’s verified decisions to one deduplicated schedule/results window and one team-box window, with weekly metadata and a protected exact-commit check. All wire calls keep UTC range boundaries across ET, MT, Pacific and Hawaii dates. IANA zones convert scheduler labels. Never narrow capture to a bare UTC calendar date or reserve only nominal calls before recursive splits.

## Replay experiment

`node scripts/simulate-intelligent-refresh.mjs --miss-primary` jointly reads actual FBS/FCS results and the private 2025–26 basketball season. This is an offline replay with no provider calls. The experiment uses estimated durations of 195 minutes for football and 130 for basketball plus known recorded basketball overtime, assumes 20 minutes of source lag and 5 minutes of validation and publication time, and drops the first slot on one representative day in each profile. It does not have historical provider appearance times, actual end times, or prior schedule versions. Those assumptions are explicit and uniform by strategy. A delayed-source sensitivity run uses `--delay-minutes 90`.

| Sample and strategy | Data requests | Builds | Simulated median / P95 minutes after assumed finish |
| --- | ---: | ---: | ---: |
| Football Oct. 25–Nov. 20, 375 fixtures, approximated current production | 57 | 19 | 575 / 815 |
| Football fixed daily, 2:45 a.m. Mountain | 78 | 26 | 755 / 2,255 |
| Football separate candidate timing, 1:45 a.m. Mountain | 78 | 19 | 665 / 2,195 |
| Football event-aware with six checks daily | 99 | 32 | 125 / 245 |
| Football hybrid candidate, 1:45 and 3:45 a.m. Mountain | 57 | 19 | 575 / 875 |
| Basketball December regular season, 1,175 fixtures, fixed | 64 | 30 | 460 / 2,080 |
| Basketball regular season, separate daily | 64 | 26 | 550 / 2,170 |
| Basketball regular season, event-aware six checks daily | 184 | 88 | 185 / 250 |
| Basketball regular season, hybrid | 58 | 27 | 550 / 970 |
| Basketball Mar. 1–Apr. 8, 626 fixtures, fixed | 81 | 38 | 460 / 880 |
| Basketball tournament period, separate daily | 81 | 31 | 550 / 970 |
| Basketball tournament period, event-aware six checks daily | 185 | 88 | 160 / 250 |
| Basketball tournament period, hybrid | 69 | 32 | 550 / 940 |

The December hybrid processed 1,126 finals by the simulation boundary, with the last calendar day’s 49 games still waiting for the next overnight window. Fixed and separate strategies had the same boundary. The six-check model caught all 1,175. The hybrid saved six metered requests and three builds versus fixed daily in December, with a later median and an earlier P95 under the injected missed-run event. It required 126 fewer calls and 61 fewer builds than the high-frequency model but did not deliver same-evening freshness. In the longer tournament window, the overnight hybrid saved twelve requests and six builds versus fixed daily. No extra 10:45 p.m. NCAA checks were included in those counts. Under 90 minutes of provider delay, high-frequency requests increased to 114 football, 192 December basketball and 198 tournament basketball. The overnight hybrid totals stayed 57, 58 and 69 with these assumed game times. This comparison does not claim production savings from moving the football schedule.

## Resource guard and launch controls

The initial reserve remains **600 football + 150 contingency** on the actual key’s shared balance, with at most 250 local basketball attempts per calendar reset and 90 in one backfill. Each retry consumes a local reservation before a network call. After this preview’s 71 successful calls, the supplied credential read 929 remaining. The conservative combined scenario is **843 remaining** if the separate observed 86 production football calls are also attributed to a shared 1,000-call balance. The key link itself still needs owner confirmation. On that conservative scenario, 93 additional calls could fit above the hard reserve, provided the rolling ledger and live remaining value still agree.

- **Nov./Dec. overlap**. The football sample supports about 64–66 result calls per 31 days under its current guard, plus up to 25 ordinary player-stat requests, a bounded playoffs allowance, and up to 16 in a rare bootstrap. A ceiling of one three-call football primary each day, five five-call player refreshes and seven optional game-night requests is 125 before manual work. Basketball’s December replay required 58, with another 10–20 allowed for schedule and result corrections or capped responses. Keep the current larger reserve until real overlap data validates a tighter one.
- **March**. Scale the 69-call 39-day replay to approximately 55 calls per 31 days under the same assumptions. Reserve another 14–20 for official NCAA game-night checks and 15 for corrections or provider issues. One-off research batches do not share this operational allowance without an explicit budget check.
- **Offseason**. Budget zero routine basketball data requests on inactive days and at most one for each approved monthly preseason probe. Use existing archive inputs for historical work. Trigger a backfill request only when the retained source is invalid or a documented revision is useful.
- **Pregame records**. Both the early and 10:15 a.m. cache-only check can identify confirmed games up to 72 hours away. The proposal leaves a ten-minute cutoff before tipoff and records missing forecast when an eligible window is missed. The private site’s separate model ledger pins actual capture timestamps, matches season and source snapshot and excludes forecasts when a later corrected tipoff proves the original capture was late. Retrospective predictions remain separate.
- **Publication quality**. The planner returns the explicit reason a run skipped, its call reservation, and candidate forecast and result IDs. Preserve the latest valid source when a fetch fails. Use content hashes, not polling timestamps, to decide whether a derived publication should change. Corrected scores are auditable and saved forecasts remain immutable.

The tested implementation is `basketball/refresh-orchestration.js` and `test/intelligent-refresh.test.js`. Tests cover named-zone DST, repeated jobs, concurrent reservation, grace after late tipoffs, postponed and TBD games, the forecast window, new tournament eligibility, provider lag, protected quota, and no-change publication. Data-client tests separately prove live quota accounting on fixtures, guarded backoff, failed snapshot preservation and local exclusive locking.

Before any production rollout, confirm the shared credential/account binding, choose one remote reservation authority for both sports, add runtime-only metered scheduling that honors the same lock, instrument source freshness for at least two real sports weeks, and review provider data display boundaries.
